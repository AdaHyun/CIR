# StageR 特征级候选重排方案

日期：2026-04-23

## 1. 目标

本轮不再继续硬堆旧的 `pseudo + bank distill` 主线，而是切换到更直接、更有把握抬高 `FashionIQ mean R@10` 的新路线：

- 保留当前最强的一阶段检索器作为 `candidate filtering`
- 新增一个轻量二阶段 `candidate re-ranker`
- 在二阶段上再接入高质量 `zero-shot / pseudo` 数据，做低风险增强

当前内部最好结果是：

- `StageP v3_safe`
- `mean R@10 = 61.3494`
- `mean R@50 = 80.8952`

当前最关键的观察是：

- `R@50` 已经不低，说明正样本经常已经进了前 50
- 真正缺的是把这些正样本从前 50 往前 10 推
- 因此下一轮最合理的提分方向不是继续大改 query encoder，而是做候选重排

## 2. 为什么换路线

上一轮 `StageP bank-distill` 的日志和 history 已经说明：

1. `bank` 确实生效了，不是“没训起来”
2. 提升主要来自 `shirt / toptee`
3. `dress` 一直是瓶颈
4. 最优点都出现在很早的 epoch
5. 后续继续训练，`dress / toptee` 会回落

这说明旧路线更像：

- 对已有表示做了一点正则化和局部重排
- 但没有形成稳定、可持续的全类别提升机制

所以这一轮不再把主要算力继续投在：

- 更复杂的 `bank` 权重
- 更复杂的 `soft/conflict` 设计
- 更复杂的 `pseudo` 直接混训

而是换成：

- `强一阶段召回`
- `轻量二阶段重排`
- `再把高质量 pseudo 只用于二阶段`

## 4. 本轮最终方法定义

本轮方法名先固定为：

- `StageR = Strong Stage-I Retriever + Feature-level Candidate Re-ranker + High-quality Pseudo for Stage-II`

具体由三部分组成。

### 4.1 StageR-A：固定一阶段检索器

一阶段直接使用当前内部最好配置：

- `StageP v3_safe`

按类别分别使用已有 best checkpoint：

- `dress`
- `shirt`
- `toptee`

这一阶段只负责：

- 提取 query feature
- 提取 candidate image feature
- 生成 train / val 的 top-K candidate list

这一阶段不再继续训练大模型主干。

### 4.2 StageR-B：训练轻量二阶段 reranker

二阶段不再做新的全量图像编码训练，而是做特征级重排。

输入：

- `q`：一阶段 query feature
- `c_i`：top-K candidate feature
- `s_i`：一阶段原始相似度

二阶段打分头：

- 输入特征为 `[q, c_i, q*c_i, |q-c_i|, s_i]`
- 输出候选分数 `r_i`

训练目标：

- `listwise cross-entropy`
- 可选小权重 `distill KL`，保持与一阶段排序的一致性

这样做的原因：

- 训练快
- 显存压力小
- 可以快速 sweep 多组参数
- 风险远低于再训一个完整大模型

### 4.3 StageR-C：只把高质量 pseudo 接到二阶段

上一轮已经证明：

- `pseudo` 直接进一阶段混训，风险高
- 但这不代表 pseudo 本身没价值

因此这一轮改成：

- human-only 二阶段先跑通
- 再把高质量 pseudo 只用于二阶段 reranker

伪样本来源：

- 已有 `structured pseudo`
- 已有 `high-quality filtered pseudo`
- 后续再补 `zero-shot / MLLM verified pseudo`

伪样本筛选规则：

只保留满足以下条件的样本：

- `quality_score` 高
- `direction_margin` 高
- `target_rank` 足够靠前
- 文本无脏词、无语义漂移

接入方式：

- 不直接和 human 1:1 混合
- 按 `sample_weight` 加权
- 先做 `human-only`
- 再做 `human + pseudo-stage2`

## 5. 实验阶段

### 阶段 R1：一阶段特征与 top-K 落盘

对每个类别分别生成：

- train image features
- val image features
- train query features
- val query features
- train top-K file
- val top-K file

默认设置：

- `K_train = 32`
- `K_val = 100`

先检查两个指标：

1. `target in top-10`
2. `target in top-50 / top-100`

如果 `top-100` 覆盖率不高，这条路线就没有价值，应立即停止。

### 阶段 R2：human-only reranker

先只用 human triplets 训练二阶段。

要跑的第一组 sweep：

1. `hidden_dim = 512 / 1024`
2. `dropout = 0.1 / 0.2 / 0.3`
3. `list_ce only`
4. `list_ce + distill`
5. `K_train = 16 / 32`

选择标准：

- 以 `mean R@10` 为主
- `mean R@50` 不明显掉

### 阶段 R3：pseudo-stage2 only

在 `R2 best` 基础上，只在二阶段接入 pseudo。

要做三组对照：

1. `human-only rerank`
2. `human + highq pseudo rerank`
3. `human + weighted highq pseudo rerank`

如果 `pseudo` 在二阶段仍拉低结果，就立刻停，不继续往这条支线加算力。

### 阶段 R4：zero-shot / MLLM verified pseudo

如果 `R3` 证明二阶段可以稳定吃下 pseudo，再补这一步。

补法不是重新造一个大系统，而是：

- 用 `MLLM` 或多教师一致性只做“验证与清洗”
- 不做大规模自由生成

目标是得到一份更小但更干净的 pseudo bank，用于二阶段。

## 7. 这轮为什么更有希望

和前几轮相比，这一轮有三个结构性优势。

### 7.1 目标和指标更一致

前几轮主要是在改 query encoder 或数据分布，但真正缺的是：

- 已召回的正确图没有排进前 10

二阶段 reranking 正好直接优化这个问题。

### 7.2 训练风险更低

前几轮每次失败都涉及：

- 大模型主干漂移
- pseudo 分布扰动
- 多损失相互干扰

这一轮先冻结强一阶段，只训轻量 reranker，搜索效率更高。

### 7.3 pseudo 的位置更合理

前几轮是：

- 把 pseudo 直接塞进主干训练

这一轮是：

- 先用 human-only 学会局部重排
- 再把 pseudo 只用于候选内判别

这比直接改全库 embedding 空间安全得多。

## 9. 最终判断规则

这轮不再以“有没有把 pseudo 系统做得更复杂”来判断成败。

只看两件事：

1. `最终 benchmark 是否超过当前内部最好`
2. `zero-shot / pseudo 是否能在二阶段形成稳定正增益`

只要这两件事成立，这一轮就比前几轮更接近题目目标：

- `Multi-modal Large Language Model-Driven Composed Image Retrieval`

因为它真正把：

- `zero-shot / pseudo 质量提升`
- `supervised CIR 提分`

连接成了一个更短、更稳的闭环。
